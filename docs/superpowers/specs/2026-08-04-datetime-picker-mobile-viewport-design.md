# 日期时间选择器移动端同屏适配设计

## 背景与根因

`ModernDateField` 的 `datetime` 模式把完整月历和 Vant 时间滚轮纵向放在同一个 `BottomSheet` 中。当前 `BottomSheet` 内层最高为 `min(78vh, 720px)`，全局底部弹窗最高为 `min(86vh, 720px)`；Vant 时间滚轮默认展示 6 行，每列高度为 264px。实际在 491 × 987 视口中，日期时间弹窗主体可视高度为 672px，但内容滚动高度为 734px，时间滚轮底部越过主体边界约 44px。

当前弹窗主体虽然使用 `env(safe-area-inset-bottom)`，但部分手机浏览器在普通网页模式下会返回 `0px`。浏览器底部工具栏又可能覆盖布局视口末端，因此仅增加安全区 padding 不能保证时间选项可见，也不能实现日期和时间同屏选择。

## 目标

- 在常见小屏手机上打开日期时间选择器时，日期月历、时间滚轮和顶部确认工具栏同屏完整可用。
- 时间滚轮底部始终与浏览器底部工具栏保持可操作间距，不依赖安全区变量一定非零。
- 点击“今天”时，在 `datetime` 模式下同时选择点击当下的日期、小时和分钟。
- 在 `date` 模式下保持“今天”只选择日期的原有语义。
- 保持取消后不修改表单、点击确定后才提交临时值的交互模型。
- 不影响 `month`、`year` 以及其他 `BottomSheet` 使用方。

## 方案选择

采用“日期时间模式专属的紧凑同屏布局”。

未采用日期与时间分步选择，因为它会增加高频记账流程的操作次数。未采用仅增加底部留白或自动滚动，因为这仍无法满足日期与时间同屏完整展示的目标。

## 组件与布局设计

### BottomSheet 视口高度变体

为 `BottomSheet` 增加显式的视口高度变体，默认值保持现状。该变体同时作用于 Vant popup 外层和 `.bottom-sheet` 内层，使二者都使用基于动态视口的高度上限，避免只放宽内层后仍被全局 `.van-popup--bottom` 的 `86vh` 上限裁切。

视口高度变体只由 `ModernDateField` 的 `datetime` 模式启用：

- 高度依据 `100dvh` 计算，适配移动浏览器工具栏展开和收起后的实际可视高度。
- 顶部保留 `var(--space-8)` 最小间距，并考虑 `safe-area-inset-top`。
- 默认变体和其他底部弹窗的高度、滚动行为不变。
- 对不支持动态视口单位的浏览器保留现有 `vh` 高度作为回退。

弹窗主体继续以 `overflow-y: auto` 作为极端矮屏兜底，但常见手机视口不需要滚动即可操作全部日期和时间控件。

### 日期时间模式紧凑密度

仅在 `datetime` 模式下应用紧凑类名：

- Vant 时间滚轮使用 3 个可见选项，每个选项继续保持 44px 高度；当前时或分位于中间，滚动手势和选中反馈不变。
- 月历继续固定显示 6 周，避免切换月份时弹窗高度跳变。
- 在视口高度不超过 740px 时缩小月历外边距、区块间距和日期行间距，并把日期格高度收敛到 40px；左右宽度和完整格子区域仍可点击。
- 月份导航按钮、“今天”按钮和顶部取消、确定操作保持现有图标与文字语义。
- 弹窗底部使用 `max(var(--space-18), env(safe-area-inset-bottom))`，即使环境安全区为 `0px` 也保留固定最小留白。

`date` 模式继续使用现有较宽松月历密度，不因本次适配发生视觉变化。

## “今天”行为

点击“今天”时只更新弹窗内的临时值：

- 先在一次点击处理中捕获同一个本地 `Date` 对象，避免日期与时间跨分钟或跨日时来自不同时间快照。
- 日期部分继续遵守 `minDate`、`maxDate` 和 `availableDates` 的可选限制。
- `datetime` 模式把临时时间同步为捕获时刻的小时和分钟。
- `date` 模式不修改或暴露时间值。
- 点击“确定”后按现有格式输出 `yyyy-MM-ddTHH:mm`；点击“取消”则丢弃临时修改。

为便于确定性测试，当前日期时间拆分逻辑放入 `calendarPicker` 工具层，并允许测试传入固定 `Date`。

## 边界与异常处理

- 当今天不在允许范围或不在 `availableDates` 中时，“今天”按钮继续禁用，不修改日期或时间。
- 时间滚轮仍限定小时 `00–23`、分钟 `00–59`。
- 横屏或极端矮屏无法满足同屏高度时，弹窗主体允许纵向滚动，顶部工具栏保持在弹窗结构之外，不随主体内容丢失。
- 页面背景、底部主导航和表单固定操作栏继续由弹窗遮罩隔离，不参与弹窗高度计算。

## 测试与验收

### 自动化测试

- 为日期工具函数增加固定时刻测试，验证能够得到正确的本地日期、小时和分钟。
- 验证 `datetime` 模式“今天”会同步当前时分，`date` 模式只产生日期值。
- 增加日期时间弹窗布局回归，至少覆盖 390 × 667 的小屏视口；断言顶部工具栏、月历、今天按钮和时间滚轮全部位于动态视口及弹窗可视边界内。
- 断言时间滚轮使用 3 个可见选项，底部仍有不小于设计最小值的可操作留白。
- 验证纯日期模式和普通 `BottomSheet` 未启用视口高度变体。

### 项目验证

- `cd frontend && npm run check:ui`
- `cd frontend && npm run build`
- 运行新增的日期时间选择器回归脚本。
- 在浅色和深色主题下手动复核 `/quick-add?type=EXPENSE` 与交易详情编辑页的日期时间弹窗。

## 非目标

- 不改为系统原生日期时间控件。
- 不拆分为日期、时间两个步骤或两个独立弹窗。
- 不改变日期格式、API payload 或交易业务规则。
- 不重构所有底部弹窗的布局和安全区策略。
- 不改变纯日期、月份和年份选择器的视觉密度。

## 预计修改范围

- `frontend/src/components/BottomSheet.vue`：增加默认关闭的视口高度变体。
- `frontend/src/components/ModernDateField.vue`：仅为 `datetime` 启用新高度与紧凑布局，并补全“今天”的当前时分行为。
- `frontend/src/utils/calendarPicker.ts`：提供可注入固定时刻的本地日期时间拆分函数。
- `frontend/tests/`：补充日期时间行为与小屏布局回归。
- `docs/frontend-ui-guidelines.md`：记录日期时间弹窗的小屏同屏与安全区规则。
