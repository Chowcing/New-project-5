# 记一笔选中项自动定位与选择弹窗稳定布局设计

## 背景

“记一笔”的模板、历史推荐和 AI 推荐可以在第 1 步修改分类、支付方式、渠道及线上平台。现有代码会在应用推荐后立即调用横向选项定位，但第 2 步尚未渲染，列表引用为空，因此进入“分类场景”后选中项可能仍在可视区域之外。

分类、支付方式和线上平台共用 `TransactionChoiceSheet`。该组件原本希望让搜索栏、选项列表和新增区域组成固定高度的三行布局，但针对 `BottomSheet` 内部节点的 scoped 深层样式没有作用到 Teleport 后的实际节点。运行时仍由外层 body 负责滚动，搜索栏会跟随内容滚动，弹窗也使用 `BottomSheet` 的默认高度。移动端聚焦搜索框时会放大这种布局变化。

## 目标

- 每次进入第 2 步“分类场景”时，分类、支付方式和线上平台的横向列表自动显示当前选中项。
- 覆盖模板、历史推荐、AI 推荐、草稿恢复、步骤返回和其他已有赋值入口。
- 线下渠道不尝试定位不存在的线上平台列表；渠道本身继续使用现有二选一控件。
- 分类、支付方式和线上平台选择弹窗在搜索框聚焦前后保持稳定高度。
- 搜索栏和底部新增区域固定，只允许中间选项列表纵向滚动。
- 保留 `.quick-choice-list` 的 `@touchmove.stop`、惯性滚动和 overscroll 约束。

## 方案

### 进入步骤时统一定位

监听 `advancedStep`。当值变为 `2` 时，在 Vue 完成 DOM 更新后调用现有 `scrollSelectedQuickOptions()`：

- 分类列表定位 `form.categoryId`。
- 支付方式列表定位 `form.paymentMethodId`。
- 渠道为 `ONLINE` 且存在 `form.onlinePlatformId` 时定位线上平台。

现有 `scrollQuickChipIntoView()` 和 `scrollSelectedQuickOptions()` 继续作为唯一滚动实现。推荐应用函数可以保留即时调用，以支持推荐在第 2 步可见时立即响应；步骤监听负责补偿第 1 步期间列表尚未挂载的情况。

### 选择弹窗布局

继续复用 `BottomSheet`，不增加新的弹窗组件。使用 `quick-choice-shell` 和 `quick-choice-body` 这两个唯一类名，把需要跨越组件和 Teleport 边界的布局规则改为可实际命中的全局选择器：

- `quick-choice-shell` 使用稳定的固定高度上限，优先采用不会随软键盘动态收缩的 viewport 单位，并保留兼容回退。
- `quick-choice-body` 使用三行 grid：搜索栏、可滚动列表、可选底部新增区；自身 `overflow: hidden`。
- `.quick-choice-list` 保持唯一纵向滚动容器。
- 搜索栏位于滚动容器之外，因此无需依赖 `position: sticky`，列表滚动时不会被遮挡。

该修改会同时改善“记一笔”和交易详情编辑中的共用选择弹窗，页面业务逻辑无需复制布局代码。

## 测试

按测试先行方式补充浏览器回归：

- 模板在第 1 步选中较靠后的分类、支付方式或平台后，进入第 2 步，当前项位于对应横向容器可视范围内。
- AI 推荐在第 1 步应用后，进入第 2 步，当前分类与线上平台位于对应横向容器可视范围内；线下推荐只验证分类和渠道。
- 打开分类选择弹窗，记录高度和搜索栏位置；聚焦并输入搜索词后，两者保持不变。
- 滚动选项列表后，外层 body 不滚动，搜索栏位置保持不变，列表自身滚动位置发生变化。

完成后运行：

- `cd frontend && npm run check:ui`
- `cd frontend && npm run build`
- 新增或扩展的浏览器回归脚本

## 非目标

- 不改变推荐算法、推荐应用规则或脏字段保护逻辑。
- 不改变分类、支付方式、平台的候选排序和数量。
- 不修改渠道二选一控件的视觉样式。
- 不重构其他 `BottomSheet` 使用方。
