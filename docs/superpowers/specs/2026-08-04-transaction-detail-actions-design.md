# 流水详情操作区视觉优化设计

## 目标

优化流水详情页“操作”区域的视觉层级，解决四个大按钮并排时显得拥挤、笨重的问题，同时保持原有业务行为、可访问性和移动端触控体验。

## 已确认方案

采用 B“设置列表”方案：

- “编辑记录”作为最高频操作，保留顶部全宽主按钮。
- “复制为今日”“设为周期”“移入回收站”放入一个统一的列表容器。
- 每个列表项由左侧语义图标、中间操作名称和右侧箭头组成，整行可点击。
- “移入回收站”仅使用支出语义色标记图标和文字，不使用整块红色按钮背景。
- 保留操作区标题“操作”和辅助说明“编辑、复制或管理这笔记录”。

## 交互与状态

- 四项操作继续调用现有处理函数，不调整路由、接口、弹窗或数据流。
- 编辑操作继续展示 `optionsLoading` 加载态。
- 复制操作继续展示 `copying` 加载态。
- 移入回收站继续展示 `deleting` 加载态，并保留现有确认流程。
- 加载期间沿用 Vant 按钮的禁用与反馈行为，避免重复提交。
- 每项操作继续使用“图标 + 文本”，保留明确的可访问名称。

## 视觉规则

- 复用 `frontend/src/styles/main.css` 和主题系统已有的颜色、间距、圆角、阴影、字号、图标尺寸及动效 token。
- 主按钮延续当前主题强调色；列表容器使用轻边框和弱背景，与详情页玻璃卡片风格保持一致。
- 列表项使用分隔线建立秩序，不再为每项操作绘制独立的大号胶囊轮廓。
- 浅色、深色主题下均需保持文本和边界可读。
- 320px 宽度下不得出现横向溢出、文字裁切或触控区域过窄。

## 变更范围

- 修改 `frontend/src/views/TransactionDetailView.vue` 中查看态操作区的模板和局部样式。
- 扩充现有 `frontend/tests/recycle-bin-ui.mjs` 回归脚本，保护操作入口、可访问名称和回收站流程。
- 不修改后端、接口类型、业务数据、编辑表单或其他页面的操作布局。

## 验证标准

- 详情页显示一个全宽编辑主按钮和一个包含三项操作的列表容器。
- 四项操作均可通过可访问角色和名称定位，并触发原有行为。
- 回收站操作保留现有确认与成功反馈。
- `npm run check:ui` 和 `npm run build` 通过。
- 在 491px 实际页面视口和 320px 窄屏视口中复查浅色页面，确认操作区层级、间距和触控区域正常。
